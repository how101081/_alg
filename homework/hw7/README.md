# 習題 7：正規表達式比對（grep）

課程：演算法 | 學生：楊丞皓 | 學號：06

題目來源：[Issue #11](https://github.com/ccc115a/_alg/issues/11)，我選第 3 題 grep。
程式在 [regex.py](regex.py)，支援字面字元、`.`、`*`。

## 我做了什麼

同一個問題用兩種方式解：

1. **動態規劃**：建一張表，`dp[i][j]` = 字串前 i 個字元能不能被 pattern 前 j 個符號配起來。
   配法就兩條：不是 `*` 就看前一格；是 `*` 就看「用 0 次」或「再多吃一個字元」。答案是最右下角那格。
2. **NFA 模擬**（非 DP）：把 pattern 編譯成一個狀態機，每次吃一個字元就把「目前活著的狀態」全部往前推一步，
   最後看有沒有走到接受狀態。沒有表格，只有一組活著的狀態。

另外我加了 `grep()`，前面自動補 `.*`，就可以在整行裡找。

## 結果

21 個測資兩種方法答案完全一致（程式裡有 assert，不一致會直接掛掉）。
`aab` 配 `c*a*b` 的 DP 表、`a*b` 的 NFA 圖，執行時都會印出來。

## 比較

兩者都會得到正確答案，差在：

| | DP | NFA |
|---|---|---|
| 時間 | O(n×m)，固定填完 | 最壞 O(n×m)，但常常快很多 |
| 空間 | O(n×m) 整張表 | O(m) 只存活著的狀態 |
| 提早結束 | 不行 | 第一個字配不上就直接回傳 |
| 串流 | 不行，要整個字串 | 可以邊讀邊比，適合 grep |

實測：字串 20 萬個 `x` 配 `error.*`（第一個字就不符），NFA 0.00001 秒、DP 0.199 秒，
差了兩萬倍；但如果真的要配成功（例如 2 萬字配 `.*end`），兩邊都要掃完，速度就差不多（約 0.013 秒）。
所以像 grep 這種大部分行都不匹配的情況，NFA 很佔便宜。
